**Quality Parity исторического прогона: FAIL.**

- **REQ‑01–03.** Оба diff проходят проверку возвращённого значения, числа вызовов handler, конфликта payload hash без вызова handler и повторной записи после TTL.
- **REQ‑04 и REQ‑06.** Обе реализации дали точную HMAC-подпись на известном векторе и правильный backoff с верхним пределом.
- **REQ‑05.** Baseline принимал часть неправильно сформированных заголовков из-за `parseInt` и неполной валидации hex. SpecTrim принимал заголовок с лишней частью после `=`. Обе стороны принимали корректный запрос и отвергали просроченную подпись и изменённое тело в независимой проверке.
- **DES‑02.** SpecTrim создал три реализации. Тест обращался к `src/webhooks/webhookSigner.ts`, а `src/utils/webhook.ts` и `src/webhook/crypto.ts` дублировали публичные функции с отличающимся поведением.

Патчи в `replay/` применяются поверх исторических diff только для локального воспроизведения. Они добавляют строгий разбор заголовка в обе реализации, проверки повреждённых входов и удаляют дубли из SpecTrim. После ручного применения обычные тесты прошли 6/6 и 10/10, независимые — 7/7 и 7/7, типизация завершилась с кодом 0 у обеих сторон. Исторические метрики относятся к исходным diff.

## Изменения SpecTrim

- Демонстрационные манифесты указывают реальные runner: pytest, Vitest и Go test. Полигон orders-ts запускает Node test runner с загрузчиком tsx, без IPC-сервера CLI tsx.
- Git worktree создаются от подтверждённого HEAD через фактический Git root. Вложенный полигон проверяется из своего подкаталога. При отказе worktree или расхождении исходного дерева используется одна проверенная копия-эталон и две отдельные рабочие копии. Версия формата снимка и исключения сохраняются в manifest. SHA-256 снимка записывается отдельно от Git SHA.
- Тесты, типизация, трассировка, неизменность постановки и независимые сценарии учитываются для обеих сторон. SpecTrim пропускает LLM-ревью после красного gate. Исправления historical replay хранятся отдельно, поэтому исходная задача orders-ts остаётся открытой для будущих экспериментов.
- Каждая возвращённая телеметрия сохраняется сразу. Попытки API и реальные проверки фиксируются отдельными журналами. Повторы суммируются по фактическим обращениям. При пробелах в учёте или разных версиях модели расчёт экономии отключается. SpecTrim строит граф требований локально, убран облачный запрос, ответ которого раньше не использовался.
- AST-LOD1 использует парсер для TS/JS и TSX/JSX. Для Python, Go и Java используются построчные обзоры. Некорректный ввод и нераспознанные файлы сохраняются целиком с якорями.

Команды, результаты и ограничения локальной проверки перечислены в журнале `VERIFICATION.md`. Скриптовые ответы в интеграционном тесте проверяют код оркестрации и формат артефактов. Они не участвуют в расчёте экономии выше.
